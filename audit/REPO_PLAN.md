## Why this split

1. **The profile is a verification surface.** Reviewers open it to check what the resume claims. Twenty-one repos you wrote, with six pinned, can be checked in 30 seconds. 186 mostly undescribed repos can't.
2. **The archive keeps history without hiding it.** Your commits in public repos under `playlikeboy-archive` still count on your contribution graph, because commits are attributed by email, not by owner. GitHub redirects old URLs and git remotes to the new owner. You can still pin an archive repo if one becomes relevant again.
3. **Copies can't be archived safely.** They aren't your work, so they count against you wherever they sit under your name. They also often ship without the original's licence notice in a visible place.
4. **Some repos can't move without breaking things users depend on:**
   - Pages sites (`playlikeboy.github.io/<repo>`) change URL.
   - jsDelivr `gh/playlikeboy/<repo>` paths for SopPlayer, AudiPlay and Picser may stop resolving.
   - Forks behind open PRs can close those PRs.
5. **Duplicates collapse to one.** debo → debo.life and index-fast → indexfast. The older twin goes to the archive with a README line pointing to the live one.

## How to move them

Transfer one repo (repeat for each name in section C):
```bash
gh api -X POST repos/playlikeboy/REPO/transfer -f new_owner=playlikeboy-archive
```
Then mark it read-only:
```bash
gh repo archive playlikeboy-archive/REPO --yes
```
Delete (sections D–G), after one last look at each:
```bash
gh repo delete playlikeboy/REPO --yes
```
Do sections D–G before C, so nothing questionable ends up in the archive. Give the org a profile README (`playlikeboy-archive/.github/profile/README.md`) saying: "Archive of Shaswat Raj's older projects and experiments. Not maintained. Current work: github.com/playlikeboy".

After moving:
- **Pages:** repos with Pages, if any end up in C, will serve from `playlikeboy-archive.github.io/<repo>`.
- **Old links:** update the portfolio, README and resume links for debo → debo.life and index-fast → indexfast.
